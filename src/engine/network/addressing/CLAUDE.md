# engine/network/addressing

The questions the engine asks of a network model, answered without moving a packet: CIDR math (`cidr.ts`: parse a range, whether an IP is inside it, `networkOf` the range of a given prefix that holds an IP, the private ranges of RFC 1918 and the loopback range of RFC 1122), the topology of an office (`topology.ts`: its LANs, the LAN of a device, whether a device has its cable and whether an actor is a client of the internet), what a router asks of its interfaces and routes (`routing.ts`) and the routing table of a device or a router (`routing-table.ts`).

- `routing.ts` answers the questions a router asks about the model: the `interfaceTowards` a LAN, router or server, whether it `ownsIp`, whether it `facesALan` (an office router) or belongs to the road to the internet, the `bestRoute` and `onwardFrom`, where it sends a packet next. `coveringRoutes` is the rule both the routers and the routing tables share: it keeps the routes that cover an IP and sorts them longest range first, `default` last, and routes of the same range keep the order they had ("Forwarding in the Internet is done on a longest-match basis", RFC 4632, §5.1, read on 2026-10-11); `bestRoute` is its first. The link between a router and a server is the /24 of the router's interface (`SERVER_LINK_PREFIX`, exported because the routing tables use it too), because an interface has no mask; a private IP at a router that faces no LAN and has it nowhere connected is `private` (RFC 1918, §3).
- `routing-table.ts` derives the routing table of a device or a router from the network; nothing stores it, so it can never disagree with the interfaces, the gateway and the routes the network already has (decided 10 of chapter 2). `routingTableOf(net, holder)` gives `TableRoute` rows (`{ to, kind, via? }`, `kind` = `connected`, `default` or `static`): a device has its LAN as a `connected` row and, when it has a gateway, a `default` row whose `via` is the gateway, and no routes of its own; a router has one `connected` row per interface and then its own routes, in the order it has them, with `default` for `ROUTE_DEFAULT`. An interface has no mask, so what a `connected` row covers is the range of the LAN it faces, the /24 of the link to a server (`SERVER_LINK_PREFIX`) or, for the link to another router, that router's own address as a /32, as in a point-to-point link. The `via` of a router's route is the IP of the interface of the next router that faces this one (`interfaceTowards`), never the id of the router; a `connected` row has no `via`. `chooseRoute(net, holder, ip)` picks the row that carries a packet with `coveringRoutes` and returns a `RouteDecision` (`holderId`, the `route` chosen as `{ to, via? }`, its `kind` and the `alsoCovered` rows that lost, most specific first), or undefined when no row covers the IP. The table has no metrics: two rows of the same range keep the order they were listed in, the `connected` rows first.
- Not here: the schemas, types and actions of the network (`src/engine/network/`), anything that moves a packet or writes a step (`src/engine/simulation/`).
- May import: `@/engine/network/schema`, `@/engine/network/types` and other files of `src/engine/`.
