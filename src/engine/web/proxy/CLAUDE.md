# engine/web/proxy

What a site that forwards does with a request, as pure functions in `proxy.ts`: which origin takes it and what message the proxy sends it. The stage that sends that message as a second connection is `src/engine/simulation/stages/web/app.ts`.

- `originOf(site, request)` is the first origin of the `proxy` of the site (`{ prefixes, origins }`, in `../schema.ts`) when the path of the request is under one of its prefixes, and nothing otherwise: then the site answers by itself. `/pedidos` takes `/pedidos` and `/pedidos/lista`, never `/pedidosx`, and a slash at the end of the prefix is ignored. The proxy uses the first origin of the list and no other: it balances nothing and retries nothing in this block.
- `upstreamMessageOf(request, clientIp)` is the message of the second connection: the same method, path, query and body, and the same `Host` as the client wrote, not the address of the origin (HTTP/1.1 asks for a Host header, RFC 9112 §3.2; nginx by default rewrites it to `$proxy_host`, while the ALB sends the name of the client without the default port, and the game follows the ALB; no text says that every proxy keeps it). The other headers the client sent travel on (a `curl` sends `User-Agent` and `Accept`) and `Content-Length` is built again from the body. `X-Forwarded-For` is the IP of the client as the proxy sees it, after the entries the client wrote, if any: a proxy adds an entry, it does not replace the list. Which entry an origin reads is the business of the origin.
- Only a server of the internet forwards: the second connection is sent from a server actor to another one, and two proxies that forward to each other are not guarded against.
- Not here: the stage and the second connection (`src/engine/simulation/stages/web/`), the schema of `proxy` (`src/engine/web/schema.ts`), the Spanish text (`src/copy/`).
