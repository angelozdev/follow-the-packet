# copy

Every Spanish text the player sees, as named constants and formatters, one file per area: the term registry (`terms.ts`), tagged text (`term-text.ts`), engine reason codes (`reasons.ts`), packet labels, and the texts of the screens in `screens/`: the roadmap, notice and entity catalog (`ui.ts`) and the incident screen (`incident-ui.ts`).

- An AWS service, resource or setting is named as the English console shows it (`Security Group`, `Internet gateway`, `Anywhere-IPv4`); the other terms keep a Spanish name (`instancia EC2`, `regla de entrada`) or are general concepts (`ping`, `CIDR`, `mínimo privilegio`). Every term has a rigorous definition of at most 120 characters; only the IP address (`IP`) and the Security Group (`SG`) have a short form.
- A term can be registered before any incident introduces it (`header`, `lan`, `ttl`, `drop`, `inbound`…): it stays inert until an incident lists it in `introduces`, and `src/levels/ladder.test.ts` then checks its definition against the order of the incidents. A definition names no term that comes later in the course, so write it for the player who has only the terms before it. The term of an ICMP message keeps the name the RFC gives it (`Time Exceeded`, `Destination Host Unreachable`); an acronym is the name and its definition expands it (`RTT`, `TTL`).
- Every entity of the map, in every variant (`EntityRef`: its kind and the variant its model gives it), names its term in `ENTITY_TERMS` (`terms.ts`), or `null` while the ladder has none; `entityTerm` reads it. The office variants have the terms of chapter 1 (`network`, `device`, `firewall` for a host firewall, `router` and `internet`); an actor has none. The other way round, a term that names an entity declares the entity whose icon goes with it in `TERM_ENTITY`: a term that names several variants shows one of them, and `packet` shows an Echo Request; a term with no entity, like `least-privilege`, has no icon. `ENTITY_REFS` lists every entity in every variant for the catalog page, and `entityName` names one as that page shows it.
- A text that uses a term tags it: `{{security-group}}` shows the term's name and `{{inbound-rule|reglas de entrada}}` shows other words. An unknown tag throws. Pieces and chips show only the name or the short form (`unofficialNames`).
- A resource's or actor's own name (`servidor2`, `Atacante`) is not a term: it is marked with `nameTag(name)`, which writes `[[servidor2]]`, and the views draw it as a name tag (monospace, in a shaded box) apart from the entity (`Security Group`, `Internet gateway`), which stays plain. Never write `[[` by hand outside `term-text.ts`. A stray `[[` or `]]` throws, like a stray `{{`. Whatever builds a text from the world marks the names it reads from it (`deviceName`, `endpointName`, `MAP_TEXT.firewall`, the titles and pieces of `game/view`); texts written by hand in an incident are not marked. A `TermText` that ends in an attribute (`aria-label`, `title`) goes through `toPlainText`.
- Not here: logic that decides outcomes (`src/engine/`), incident content (`src/levels/`).
- Text follows `.claude/rules/rigorous-plain-copy.md`.
- May import: `@/engine`.
