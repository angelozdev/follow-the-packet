# game

The session of one incident, as a pure reducer: the current world, the run of every flow, the packets the player sent (the last one of each combination of chips, with the number of its send), the tasks (done or not, read from the runs and the sent packets at once), the sent solution and Lucía's reply, hints, the explanation and the stars. The middle star depends on the mechanic: only what is needed for a filter, no hints for a send or an identify, no hint in any case for a diagnose. What the map and the panels show lives in `view/`.

- Every run (a flow or a sent packet) carries `by`: the ids of whoever answered, warned or dropped the packet (a device, a router or an actor; for a packet a firewall dropped, the ids of the firewalls of that device; for a local error such as `no-route`, the sender; none when the network lost it). A send task holds when the outcome of the trace is the expected one and, if it names `by`, that id is among them.
- What a run shows depends on what the player knows (`Session.known`, passed to `runFlows` and `sendPacket`): `blocked` is true only when the firewall that dropped the packet is a known term. When it is not, the run is `hiddenStop` and `blocked` is false, so the packet leaves the lost stamp and ends at the door of its device. A warning that came back (`Trace.notice`) is part of the run as `warning`, with the term that names it and who generated it (`router`, or `sender` when the sender's own device did): it is left out while its term is unknown, and the packet is seen as one that nobody answered. Nothing else changes: the outcome, `reached`, `replied` and `by` are those of the trace, because the tasks read them.
- In a send incident whose routers wait for a traceroute (`revealsRoutersByTraceroute`), a packet that is not a traceroute and that a router dropped without a warning is also `hiddenStop`, before and after a traceroute has named the routers (`revealedRouterIds`, `view/revealed-routers.ts`, only decides which router pieces are drawn): a ping alone never reveals where it died, and a traceroute only says the break is very probably after the last router that answered, so the packet leaves and stops just outside its device with the lost stamp and never moves. `sessionReducer` and `startSession` set it on every run after each action (`hideStopsOutOfSight`, `src/game/flow-runs.ts`); nothing else about the run changes.
- A traceroute sent from a terminal is one entry of the sent packets: the run of the last probe it sent (the one that ended it), with all its probes in `route`. A single packet has no `route`. What the terminal prints for it is `tracerouteLines` (`view/cards/`).
- In an identify incident the session holds `answers`: the chip confirmed for each tray of each device (`answers[deviceId][trayId]`). It starts with the `initialPick` of every tray that has one, so starting the incident again puts them back, and a starting pick completes no task by itself. The action `answerCard` (`{ deviceId, picks }`, `picks` by tray id) saves the picks the card confirms; a card, a tray or a chip the incident does not offer is left out, an answer that changes nothing returns the same session, and a change takes Lucía's reply away. An identify task holds when the confirmed chip for its device and tray is the one it expects (`taskHolds` and `failingTaskIds` take `answers` as their last argument). A pick only counts once the card confirms it: the draft before that is the card's own state (`src/ui/`), never the session's.
- A rule move (`placeRule` and `removeRule`) works on one direction of a firewall (`direction`, inbound by default). `canConfigure(session, firewallId, direction?)` asks the ladder (`Session.parts.inboundRules` and `outboundRules`, per kind of firewall) for that direction, or for either one when none is given (a piece is configurable if any direction is). A rule placed in the other direction than the one the flow needs changes the world and leaves the runs as they were: a host firewall with its outbound side closed keeps stopping the ping after an inbound rule.
- In a send incident with settings (`send.settings` in the contract of `src/levels/`) the session also takes the action `setSetting` (`{ deviceId, settingId, chipId }`): it sets the default gateway of the device, runs the flows again and clears `sent`, because the stamps of the packets sent before described the old world. The send number goes on counting, Lucía's reply goes away, and a chip already in effect, one the incident does not offer or an incident that is not a send return the same session.
- In a diagnose incident the session is on one case at a time (`caseIndex`, from 0): `world` is the world of that case (`Session.start`, the world the incident starts from, plus the changes of the case: `caseWorld`), and `sent`, `hintsShown` and `named` (the options of the cause question named so far in this case) belong to the case. `currentCase` is the case, `sendingOf` whatever offers the send chips now (the send incident, or the case), `hintsOf` the hints in play and `canAskHint` whether one is left to show (not once the case is closed). The action `nameCause` (`{ index }`) names an option: a wrong one is kept in `named`, so its feedback shows and the player tries another; the right one closes the case, pushing `{ picks, hints }` onto `caseResults` (`picks`: the options named in order, the last the right one; `hints`: those asked in the case). The case stays on screen, closed, so the player reads the feedback of the right option; `nextCase` then opens the next one (its world; `sent`, `hintsShown` and `named` start empty; the send number goes on counting). The last case closed ends the incident: the phase goes to `explaining` and the middle star is settled (`noHintInAnyCase`), and `showResult` takes it to `result` with no explanation chosen. An option out of range, one already named, any naming in a closed case, `nextCase` before the case is closed, and `submit`, a rule, a card answer, a setting or an explanation choice do nothing. The explained star is `everyCauseAtFirstTry` (every case closed, each with the right option as the first one named); `firstTry` is the same fact for one case, and the result card uses it for the cases that missed (`caseSummary`).
- No game clock: the session changes only with player actions; nothing here reads the clock, storage or the DOM.
- Not here: network rules (`src/engine/`), incident content and the world chain (`src/levels/`), drawing (`src/scene/`, `src/ui/`).
- May import: `@/engine`, `@/copy`, `@/levels`. Files inside import each other directly (`./x`, `./view/x`, `@/game/<folder>/x`).
