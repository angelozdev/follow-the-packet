# ui/catalog

The `#/entidades` page: the entity catalog for design review, with every piece on one canvas (`src/scene/map2d/catalog/`), every icon with its name, and every element of the interface in every variant and state (`interface-section.tsx`). The roadmap does not link to it.

- The interface section draws each element the way the screens draw it. When a screen gains an element, a variant or a state, the section gains its specimen, so the capture covers it.
- `entities.browser.test.tsx` (Task M22 of the 2D plan; until then `tests/e2e/entities.spec.ts`) draws this page in Vitest in headless Chromium, over the real stylesheet, and holds the two captures and the tests that read what the browser draws of its specimens. The captures are `toMatchScreenshot` of the region «Piezas del mapa» and of the region «Elementos de la interfaz» with the focus ring on an option, with zero tolerance (`allowedMismatchedPixelRatio`, `allowedMismatchedPixels` and `threshold` at 0, except the edges pixelmatch counts as anti-aliasing), and their references are in `__screenshots__/` (its guide says how to record one on purpose). Both are taken still: the preference for less motion is emulated through the protocol of the browser (`emulateReducedMotion` of `@/testing/browser-play`, given back after each test), the mouse is moved away before the page is drawn, and the focus goes to the option with a Tab first, so the ring is drawn as for a keyboard (a script focus after a click draws none).
- The window of the capture tests is 1280×3000 (`page.viewport`, given back after each test), taller than the tallest region, which is the interface section, 2828 px. Measured on 2026-10-20: with a window of 1000 px, 2,256,656 of the 3,484,096 pixels of the interface capture differ, so a region taller than the window is not captured the same. Raise the window before a specimen makes a region taller than it. The captures are drawn with the system fonts of the machine (the browser project loads no Google Fonts), so after an OS or browser update that changes those fonts, look at the diff images and record again on purpose.
- The tests that put a specimen in a card of the map (a long `Table`, the unfolded output) copy it into a `.map-card` with the width and the height cap of a card (`--card-width` and `--card-room`), inside the container of the render, so Testing Library takes the copy down with the page; the others read the boxes of the specimens against the region the capture takes. The test of the letters of the options reads the accessibility tree and the DOM snapshot of the page of the test through the protocol of the browser (`Page.getFrameTree` gives the frame, `Accessibility.getFullAXTree` its tree, `DOMSnapshot.captureSnapshot` the text the layout draws, which includes the letters that CSS counters draw).
- Not here: the pieces, the icons and the canvas (`src/scene/`), the names of the variants and the sample texts (`src/copy/screens/ui.ts`).
- May import: `@/scene`, `@/copy`, `@/design`, other files of `src/ui/` (`@/ui/<file>`), and only types from `@/engine`.
