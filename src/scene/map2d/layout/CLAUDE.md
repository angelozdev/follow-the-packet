# scene/map2d/layout

Where things go on the 2D map, as pure functions: no React, no DOM, no clock, no randomness. The same input gives the same boxes. `metrics.ts` measures labels, `graph.ts` is the graph of links and `stations.ts` names where a packet stops; the layout of the map builds on the three.

- `metrics.ts` measures labels. Every label of the map is monospaced, so its width is its characters and not a table of glyphs: `ceil(characters × CELL) + LABEL_PAD`, with `CELL` 7.2 px (0.6 em at 12 px) and `LABEL_PAD` 14 px (6 px of padding and 1 px of border on each side). `LOCK_WIDTH` (26 px) and `ALERT_WIDTH` (22 px) are added when the label wears the lock or the alert; both are starting values derived from the CSS and not measured: the browser test of Task M21 measures them and corrects them here. Widths are whole pixels rounded up, so the model errs wide against the cell; that it never falls short of the DOM is for the browser test of Task M21 to show, which compares the two. `characterCount` counts what the player sees: an arrow takes one cell, and so does an accented letter, composed or not.
- `labelLines` splits the label of a firewall into the name of its term and the name of its resource; `labelBox` gives the box of those lines: as wide as the longer one, 20 px tall for one line (`LABEL_HEIGHT`) and 16 px more for each other (`LINE_HEIGHT`), so 36 px for two. `MAX_NAME_LENGTH` (32) is the longest name a world may have, which makes a label of 245 px; a test walks every registered world.
- Where the 0.6 em comes from (read on 2026-10-12, spec «El ancho de las etiquetas»): the file of IBM Plex Mono v20 that Google Fonts serves for `index.html` (subset `latin`, `https://fonts.gstatic.com/s/ibmplexmono/v20/-F63fjptAgt5VM-kVkqdyU8n1i8q131nj-o.woff2`), read with `fontTools` 4.63.0: `unitsPerEm` 1000, `isFixedPitch` 1, and 221 of its 229 glyphs advance 600 (the other 8 are combining marks, which advance 0). The same tool read Menlo (`/System/Library/Fonts/Menlo.ttc`), which advances 0.602 em, and SF Mono (`SFNSMono.ttf`, the font of `ui-monospace` on macOS), which advances 0.618 em. That is why the map's font stack leaves `ui-monospace` out (Task M11), and why a browser test compares this model with the DOM.
- The arrow `→` (U+2192) is not in the file that is served, so the browser draws it with another font of unknown width; the label of a packet fixes its width with `textLength` in SVG (Task M13), and here the arrow counts as one cell.
- `graph.ts` is the graph of the map: `Graph` has nodes (a station name and its point) and edges (two station names and, optionally, the `bends` where the drawn link turns, listed from `from` to `to`; a link can be walked either way). `route(graph, stations)` completes the legs between the stations it is given with the shortest way along the links (Dijkstra; a bend counts in the length of its link) and returns the points, the bends included. Between two ways of the same length the one that goes through the node that comes first in `nodes` wins, at every link of the way, whatever the order of the edges; so the same graph always gives the same way. It throws when a station is not in the graph or when no links join two of them. `lengthOf` and `positionAt` are `cumulativeLengths` and `pointAt` of `src/scene/layout.ts`, with the same results and another form (jscpd forbids a copy while both files exist); they measure and walk the points `route` returns. `Point` is its own type: this folder does not import the 3D `layout.ts`, which Task M24 deletes.
- `stations.ts` is `stationsFor`, the 2D replacement of `pathFor`: the stations a packet stops at, as names and not coordinates (`startsOnMap` replaces the one of `layout.ts`). It takes `Drawn`, what the map draws by id (the layout builds it): each drawn device with the id of its bus (a floor, a subnet, or one name the layout gives the bus of an office with neither), the clients and the servers, the routers along the main line from the office outward, the gateways of another office (off that line), `edge` (the lone edge of a world with no routers) and `internet`. It reads the `Trace` for every outcome and decides none. It names a station only when the map draws a piece for it, and never twice in a row. `station` holds the builders of the names, so the layout names its nodes with the same code; the tests spell the names out. The vocabulary (spec «Piezas, enlaces y estaciones», plus what the plan did not name):

  | Station | Where | Says |
  |---|---|---|
  | `door:<id>` | the edge of a device, a server or a client that faces its link | it arrived at the piece, or it starts there |
  | `doorstep:<device>` | 62 px from the edge, on the link | it never left the device |
  | `firewall:<device>` | the bar | a firewall the player knows stopped it |
  | `road:<device>` | where the link meets the bus | it was lost in the road of its network |
  | `bus-end:<bus>` | a stub of 40 px past the last device of that bus | nobody has the IP (a device sending in a VPC) |
  | `router:<id>`, `internet` | the icon | it died at that router or in the internet |
  | `edge` | the lone edge | it crossed the edge of a world with no routers |
  | `mid:<a>-<b>` | the middle of the link between two stops of the main line | a router the map does not draw dropped it |
  | `line-end` | a stub past the last stop of the main line | only inside a `mid`: it died past everything drawn |

  `mid`: the stops of the main line, in order, are `edge`, `router:<id>` for each router, `internet` and `door:<server>` for each server. `a` is the last stop the packet crossed and `b` the next one; from the road of the sender, `a` is `bus:<bus>` (where the trunk of its bus leaves it) and `b` the first stop; with nothing drawn beyond, `b` is `line-end`. A packet that crossed something off the line (a client, a gateway of another office) has no `mid` and ends there. The layout must give a node to every `mid` it can need, `bus:<bus>` and `line-end` included.
- A packet whose sender is not drawn has no stations; `startsOnMap` says so first. A packet from the internet to a public IP that no router owns ends in the internet, since no bus is its own.
- Not here: drawing (React and SVG), measuring the DOM (a browser test does that), the Spanish text of a label (`src/copy/`), where a card opens (`cards/`).
- May import: `@/copy`, only types from `@/engine`, and other files of `src/scene/map2d/`. Its tests also read `@/engine` (to run `simulate`), `@/levels` and `@/testing`.
