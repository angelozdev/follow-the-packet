# KISS — Keep It Simple

Prefer the simplest solution that satisfies today's requirement. Don't design for hypothetical future cases (YAGNI), don't add layers of indirection, flags, or configuration that nothing uses yet.

Balance against [[dry]]: don't repeat real logic, but don't abstract before it's needed either. When in doubt between "simpler" and "more reusable/flexible", simple wins until a second real use case justifies the abstraction.
